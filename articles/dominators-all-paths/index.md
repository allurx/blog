从程序入口走到某个操作之前，一定会经过哪段代码？只沿着一次运行轨迹往前找，能得到“这次经过了哪里”，却不能排除另一条分支绕过它。编译器需要的是对所有路径都成立的判断。

控制流图中的支配关系正好回答这个问题。本文从一个带分支和循环的有向图出发，用集合交集计算必经节点，再说明为什么不能把它等同于“出现得更早”或“直接连着目标”。只需了解有向路径、集合交集与并集，不依赖具体编程语言。

## 所有路径都要经过，才叫支配

控制流图把基本块作为节点，把可能的控制转移作为有向边。基本块是一段从入口进入、内部按顺序执行的代码。以下只讨论从单一入口 $E$ 可达的节点，路径包括起点和终点。

若从 $E$ 到 $n$ 的每一条路径都包含 $d$，就说 $d$ 支配 $n$。因此，每个节点支配自己，入口支配所有可达节点。排除节点自身后，称为严格支配。[Cornell CS 6120 的支配关系定义](https://www.cs.cornell.edu/courses/cs6120/2025fa/lesson/5/)采用的就是这种全路径条件。

考虑下面这张图。表中列出了全部边，没有省略其他跳转：

| 节点 | 可以转移到 |
| --- | --- |
| E | A、B |
| A | C |
| B | C |
| C | D、X |
| D | C |
| X | 无 |

从 E 出发，先选择 A 或 B，再到 C。C 可以进入 D，D 又返回 C，也可以直接转到出口 X。

A 不支配 C，因为路径 E、B、C 绕过了 A。B 也不支配 C。C 则支配 D 和 X：无论走哪条初始分支，也无论在循环中停留多少次，第一次进入 D 或 X 前都必须经过 C。

D 不支配 X，因为 E、A、C、X 不经过 D。即使在某次实际运行中 D 执行了一万次，也不能改变这个结论。支配关系关心是否存在绕行路径，不关心路径出现的频率。

## 前驱的共同必经点，也是当前节点的必经点

记 $\operatorname{Dom}(n)$ 为支配 $n$ 的节点集合，$\operatorname{Pred}(n)$ 为直接指向 $n$ 的前驱集合。入口的集合固定为：

$$
\operatorname{Dom}(E)=\{E\}
$$

其他可达节点满足：

$$
\operatorname{Dom}(n)=\{n\}\cup
\bigcap_{p\in\operatorname{Pred}(n)}\operatorname{Dom}(p)
$$

为什么是交集？到达 n 的最后一步必须来自某个前驱。只有每个前驱的路径都绕不开的节点，才不会因为选择不同前驱而失去“必经”资格。最后加上 n 自己，因为到达 n 的路径必然包含 n。[WPI 的支配集合算法](https://web.cs.wpi.edu/~kal/PLT/PLT8.6.3.html)给出了这一递推关系。

更严格地说，对 $d\ne n$，如果 d 不支配某个前驱 p，就存在一条绕过 d 的入口到 p 的路径。接上 p 到 n 的边，仍然绕过 d。反过来，若 d 支配每个前驱，则任何到 n 的路径在最后一步之前就已经过 d。这说明交集表达的恰好是所需条件。

本例中，C 的前驱包括 A、B 和 D。不能因为 D 是循环中的节点，就擅自把它从前驱集合删掉。循环让方程相互依赖：求 C 需要 D 的集合，求 D 又需要 C 的集合，所以不能简单地从入口向后计算一遍就结束。

## 从候选全集开始，反复排除不成立的关系

令所有可达节点组成集合 $V=\{E,A,B,C,D,X\}$。初始化时，入口只保留自身，其他节点暂时把 V 全部当作支配者候选。随后反复应用方程，直到所有集合不再改变。

下面采用同步更新：每一轮只读取上一轮的结果，避免把遍历顺序混入表格。

| 节点 | 初始 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
| --- | --- | --- | --- | --- |
| E | {E} | {E} | {E} | {E} |
| A | V | {E,A} | {E,A} | {E,A} |
| B | V | {E,B} | {E,B} | {E,B} |
| C | V | V | {E,C} | {E,C} |
| D | V | V | V | {E,C,D} |
| X | V | V | V | {E,C,X} |

第 2 轮，C 使用上一轮的三个前驱集合：

$$
\{C\}\cup\bigl(\{E,A\}\cap\{E,B\}\cap V\bigr)=\{E,C\}
$$

A、B 分别被另一条入口分支排除，D、X 也不再是候选。第 3 轮，C 的结果传给 D 和 X。再计算一轮没有变化，算法结束。

实际实现也可以就地更新，在同一轮利用刚算出的集合。那样的中间表和轮数可能不同，不能拿这里的“三轮”当成固定性能指标。只要持续更新所有需要处理的节点，直到稳定，就能得到相同的最终关系。

为什么从全集出发？交集会不断去除候选。真正的支配者不会被误删：如果 d 确实支配 n，那么除 n 自身之外，它也支配每个前驱，因而能留在交集中。有限个节点之间只有有限个候选关系，集合持续缩小，最终必然停止。

还能证明错误候选不会永远留下。若 d 不支配 n，就存在一条入口到 n 的路径绕过 d。从入口开始，d 的缺席会沿这条路径逐步传播，每轮至少向前推进一条边，最终把它从 n 的候选集合排除。这说明收敛结果不仅稳定，而且符合全路径定义。

## 空集初始化可能稳定在错误答案上

考虑更小的图：入口 E 指向 L，L 有一条指回自己的边。正确答案显然是 $\operatorname{Dom}(L)=\{E,L\}$，因为第一次到达 L 必须从 E 出发。

它的方程却包含自身：

$$
\operatorname{Dom}(L)=\{L\}\cup
\bigl(\{E\}\cap\operatorname{Dom}(L)\bigr)
$$

若从空集开始，第一次得到 {L}，以后仍然是 {L}，遗漏的 E 不会自动补回来。而从 {E,L} 开始，正确结果立即保持不变。

所以“反复套方程直到不动”并不充分，还要选择正确的初值。此处从全集逐步收缩，保留的是符合入口边界条件的最大不动点；空集向上增长可能落在另一个不动点。循环正是把这个区别暴露出来的地方。

## 支配树的父节点不一定是前驱

把最终集合里的冗余祖先关系压缩，就得到支配树。对非入口节点 n，它的直接支配者是离 n 最近的严格支配者：其余严格支配者都支配这个直接支配者。对于单入口的可达控制流图，这个节点唯一。

本例的直接支配关系如下：

| 节点 | 直接支配者 |
| --- | --- |
| A | E |
| B | E |
| C | E |
| D | C |
| X | C |

这里 E 是 C 在支配树中的父节点，但原图根本没有 E 到 C 的边。原图表示“一步能去哪里”，支配树表示“有哪些层层嵌套的必经点”，两者的边不能互换。

支配树适合快速回答一个节点是否支配另一个节点：看前者是否为后者的祖先，并包含节点等于自身的情况。它不保留原图全部控制转移，不能拿来模拟程序执行。

## 用另一种方式检查答案

对可达目标 n 和候选 d，暂时禁止经过 d，再从入口做一次可达性搜索。如果仍能到 n，找到的路径就是“不支配”的证据；如果到不了，d 就是必经节点。删除入口会让所有目标不可达，删除目标本身也会让它不可达，恰好对应入口支配所有节点、节点支配自身。

这个方法可以独立检查前面的集合结果。例如禁止 A，仍可沿 E、B、C、X 到 X。禁止 C，D 和 X 都到不了。实现时无需真的修改图，在搜索时跳过指定节点即可。对每一对节点都做搜索通常不适合大图，但很适合小图测试和定位集合算法中的错误。

最后要明确分析边界。不可达节点应先排除，否则“所有入口路径”可能变成对空集合的陈述，前驱交集也失去本文假设。异常跳转、提前返回等边若属于所分析的程序模型，就必须纳入图中，漏边可能错误地制造必经点。

即使控制流图完整，图上的路径也未必都能被某组实际输入执行。例如不同分支条件之间可能存在关联。按图结构证明的支配关系仍适用于实际执行，但图中一条不可行的绕行路径可能让分析错过语义上成立的必经关系。

支配只证明控制经过，不证明经过后建立的条件一直有效。某个检查块支配使用块，并不代表中途没有修改被检查的数据。判断优化或程序行为时，应把全路径的控制保证与数据是否变化分别分析。
