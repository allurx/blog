给变量的每次赋值换一个名字，可以让数据来源更清楚：`x = 1; x = x + 2` 改写为 `x0 = 1; x1 = x0 + 2`，第二次计算依赖哪个定义一目了然。但遇到分支，单纯编号就不够了。两条路径分别产生了 `x1` 和 `x2`，汇合后的代码究竟该使用谁？

静态单赋值形式（Static Single Assignment，SSA）用 φ 节点表达这种选择。本文先解释它如何保存分支语义，再用一个嵌套分支推导插入位置，最后说明循环为什么也需要它。示例均为解释控制流与数据流的伪代码，不对应某个编译器的可执行语法。只需理解赋值、条件分支和循环。

## 一个名字对应一个定义

SSA 要求每个值名在程序文本中只有一个定义位置。这里的“静态”很重要：位于循环里的那条定义可以执行多次，并不要求整个运行过程只执行一次。函数参数也作为进入函数时已有的定义处理。[Cornell 的 SSA 课程讲义](https://www.cs.cornell.edu/courses/cs6120/2025fa/lesson/6/)明确区分了静态定义位置与动态执行次数。

考虑两个分支分别计算价格，随后统一使用结果：

```text
Entry:
    if member goto Discount else Regular
Discount:
    price = 80
    goto Join
Regular:
    price = 100
    goto Join
Join:
    return price + 5
```

`Entry` 等标签表示基本块，即从块入口进入、按顺序执行到末尾的代码段。`goto` 表示控制流边。把两次赋值分别命名为 `price0`、`price1` 后，在 Join 开头加入一个新定义：

```text
Discount:
    price0 = 80
    goto Join
Regular:
    price1 = 100
    goto Join
Join:
    price2 = phi(Discount: price0, Regular: price1)
    return price2 + 5
```

本文把 φ 的每个输入写成“前驱块：值”。从 Discount 到达 Join，就选择 `price0`；从 Regular 到达，就选择 `price1`。两种路径分别返回 85、105。φ 不会求和或平均，也不要求先执行两条分支来准备所有输入。未走过的分支可以根本没有产生对应值。

这也解释了 φ 输入的特殊位置：输入值的使用应当理解为发生在对应的入边上。例如 `price0` 只需在 Discount 到 Join 的边上可用，无需在 Regular 路径上可用。[LLVM 的 φ 指令定义](https://llvm.org/docs/LangRef.html#phi-instruction)采用这种入边语义，并要求 φ 指令集中位于基本块开头。这里引用其语义，不把上面的伪代码当成 LLVM IR。

## 从支配关系找到值需要汇合的地方

如果所有从入口到块 Y 的路径都经过块 D，就说 D **支配** Y。每个块支配自身；排除自身后叫严格支配。可以把它理解为图上的“必经”条件，详细计算方法见[支配关系：怎样找出控制流中的必经节点](/dominators-all-paths/)。

对于普通使用，SSA 定义必须支配使用位置；同块内还要保证定义排在使用之前。这样，每次到达使用点都已经有唯一的来源。上例中 Discount 不支配 Join，因为 Regular 路径能绕开它。Regular 也不支配 Join，所以不能直接选其中一个分支的名字供所有路径使用。

支配边界（dominance frontier）描述一个区域刚刚失去这种全路径保证的位置。Y 属于 D 的支配边界，当且仅当：

1. D 支配 Y 的至少一个前驱。
2. D 不严格支配 Y。

记作：

$$
\operatorname{DF}(D)=\{Y\mid \exists P\in\operatorname{Pred}(Y),\ D\text{ 支配 }P,\ D\text{ 不严格支配 }Y\}
$$

这个定义及后面的迭代构造见[上海交通大学的 SSA 讲义](https://jhc.sjtu.edu.cn/public/courses/CS263/Lecture_notes_20210602___SSA_1.html)。先看无环的价格例子：Discount 支配自身，而它正是 Join 的前驱；Discount 又不支配 Join，因此 Join 属于其支配边界。在这个位置，来自 Discount 的值开始与其他路径的值相遇。

支配边界由控制流图决定，本身不区分变量。以下只分析单一入口可达的块，并假定每条路径上的读取都有先前定义，不处理未初始化变量。实际构造 SSA 时，要针对每个变量，从包含其定义的块出发，查找需要插入 φ 的位置。

## 新插入的 φ 也会产生下一处汇合

嵌套分支能说明为什么只检查原始赋值一次还不够。下面的程序先给 x 默认值；只有 enabled 为真时才进入内部分支：

```text
E:
    x = 0
    if enabled goto A else H
A:
    if chooseLeft goto B else C
B:
    x = 10
    goto J
C:
    x = 20
    goto J
J:
    goto H
H:
    return x
```

全部边已列在伪代码中。E 是入口，H 是最终汇合点；J 只汇合 B、C 两条内部路径。原始 x 的定义块集合为 `{E, B, C}`。

先算出与本例有关的支配边界：

| 块 | 支配边界 | 原因 |
| --- | --- | --- |
| E | 空集 | E 严格支配其他所有块，且没有指回 E 的边 |
| B | {J} | B 支配前驱 B，但 C 路径绕过 B 到达 J |
| C | {J} | 与 B 对称 |
| J | {H} | J 支配前驱 J，但 E 到 H 的直接路径绕过 J |

B 的支配边界不包含 H。H 的两个前驱是 E、J，B 不支配其中任何一个：E 在 B 之前，而到 J 可以走 C。C 同理。

因此，只取原始定义块的支配边界，并集只有 `{J}`。在 J 插入 `x = phi(...)` 后，J 自己也成为 x 的定义块。继续检查 J 的支配边界，才会发现 H 还需要一个 φ，用来合并“内部选择的结果”与“入口默认值”。

这就是**迭代支配边界**的用途。可用一个待处理集合实现：初始放入原始定义块；每取出一个块，就在其支配边界中尚未放置该变量 φ 的块上插入 φ，并把这些新定义块加入后续处理。每个变量在同一块至多插入一次，有限图上的过程最终停止。若一个块已有原始定义，它本来就在待处理范围内，无需重复加入。

确定位置后，再为定义和使用一致地重命名，得到：

```text
E:
    x0 = 0
    if enabled goto A else H
A:
    if chooseLeft goto B else C
B:
    x1 = 10
    goto J
C:
    x2 = 20
    goto J
J:
    x3 = phi(B: x1, C: x2)
    goto H
H:
    x4 = phi(E: x0, J: x3)
    return x4
```

从输入到返回值可以直接核对：

| 输入条件 | 实际路径 | J 选择的值 | H 选择的值 |
| --- | --- | --- | --- |
| enabled 为假 | E → H | 不执行 J | x0，即 0 |
| enabled 为真，chooseLeft 为真 | E → A → B → J → H | x1，即 10 | x3，即 10 |
| enabled 为真，chooseLeft 为假 | E → A → C → J → H | x2，即 20 | x3，即 20 |

每个使用都有明确的定义，每条路径的结果也与原程序一致。若删去 H 的 φ 而直接返回 x3，第一行路径根本没有定义 x3；若统一返回 x0，后两行的结果又会错误地变成 0。

## 循环会把块自身放进支配边界

支配边界的第二个条件是“不严格支配”，不能改成“不支配”。原因在循环中最清楚。设入口 E 初始化计数器，循环头 L 判断条件，循环体 Body 更新计数器后返回 L：

```text
E:
    i0 = 0
    goto L
L:
    i1 = phi(E: i0, Body: i2)
    if i1 < 3 goto Body else Exit
Body:
    i2 = i1 + 1
    goto L
Exit:
    return i1
```

首次进入 L 来自 E，所以 i1 取 0。随后每次从 Body 返回，i1 取上一轮算出的 i2，依次为 1、2、3。读到 3 时退出。`i1`、`i2` 在文本中都只有一个定义位置，循环重复执行这些位置不违反 SSA。

L 支配 Body，而 Body 是 L 的前驱。L 又不严格支配自身，所以 L 属于 `DF(L)`。这不是图论定义中的例外，而是同一个条件自然覆盖了回边。若把条件误写成“不支配”，就会因为 L 支配自己而漏掉这种情况。

`i2` 的定义虽然在文本中排在 φ 后面，但它仅在 Body 到 L 的回边上被选择。首次进入 L 时不读取 i2，因此不存在要求“先算出未来值”的矛盾。

## 放置规则与实际需要还要分开判断

迭代支配边界给出基于图结构的 φ 放置方法，但并不意味着每个多前驱块、每个变量都必须保留 φ。如果汇合后的 x 在读取前无条件被重新赋值，入边上的旧值就没有用途。构造时结合活跃性分析，可以只为进入块时仍可能在被覆盖前读取的变量插入 φ，这通常称为 pruned SSA；也可以先构造，再删除无用定义。关于只保留活跃 φ 的形式，参见 Zhao 等人的[SSA 优化形式化验证论文](https://acg.cis.upenn.edu/papers/pldi13_verification_ssa_optimizations.pdf)。

反过来，只有一条分支修改 x，另一条保留旧值，仍可能需要 φ。需要汇合的是来自不同路径的定义，不要求每条分支都出现一条新赋值。

还有两个实现边界。第一，同一块开头的多个 φ 在语义上同时读取入边值，不能随意当成顺序覆盖的普通赋值，否则循环中的交换会丢失原值；[Cornell 讲义中的交换示例](https://www.cs.cornell.edu/courses/cs6120/2025fa/lesson/6/#subtleties-in-classic-ssa)展示了这种错误。第二，本文处理的是标量值名；把指针变量变成 SSA，并不会自动消除它所指内存的别名和写入问题。编译器仍需相应的内存分析。

读 SSA 时，可以先沿控制流找出进入块的边，再在 φ 的对应输入中追踪定义。构造 SSA 时，则先找定义块，沿支配边界反复补齐汇合点，再一致地重命名。两者连接起来，才能既看清每个值从哪里来，又保留原程序在分支和循环中的行为。
