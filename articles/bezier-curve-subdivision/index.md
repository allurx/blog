在矢量编辑器里，给一条曲线添加节点和拖动节点是两件事：点击“添加”的那一下，轮廓应当纹丝不动。找到曲线上的新节点只解决了一半问题。原来一段曲线有两个控制柄，拆开后两段各需要两个。新的四个控制柄应该放在哪里？

来看一段 SVG 路径。下面是 `<path>` 元素的 `d` 属性值：`M` 移到起点，`C` 后面依次写两个控制点和终点，坐标都是绝对值。起点和终点在曲线上，中间两个控制点用来牵引曲线，一般不在曲线上。

```text
M 0 0 C 0 64 64 64 64 0
```

我们在参数 $t=1/4$ 处切开它。这里的四分之一指参数区间 $[0,1]$，不代表已经走过四分之一的弧长。目标是得到两条同样由 `C` 表示的曲线，拼起来与原来的整段重合。

## 求切点时，把中间结果留下来

从点 $X$ 朝点 $Y$ 走四分之一，得到 $X+(Y-X)/4$。对原来的四个点从左到右两两做这一步，就得到三个点。再在三个点间做同样的插值，得到两个点。最后一次插值得到切点。这就是 de Casteljau 算法；“从左到右”指路径中点的先后顺序，不要求横坐标递增。

| 层 | 按路径顺序排列的点 |
| --- | --- |
| 原始控制点 | $P_0=(0,0)$，$P_1=(0,64)$，$P_2=(64,64)$，$P_3=(64,0)$ |
| 第一次插值 | $A=(0,16)$，$B=(16,64)$，$C=(64,48)$ |
| 第二次插值 | $D=(4,28)$，$E=(28,60)$ |
| 第三次插值 | $F=(10,36)$ |

例如，$D$ 从 $A$ 朝 $B$ 移动了 $(4,12)$。接着从 $D$ 朝 $E$ 移动 $(6,8)$，便到达曲线上的 $F$。如果只想查询一个点，计算到这里就结束了；要拆分曲线，刚才算过的点正好派上用场。

沿表的左边从上往下读，得到前一段的四个控制点 $P_0,A,D,F$。沿右边从下往上读，得到后一段的 $F,E,C,P_3$。两段共用 $F$。写回路径时，第二个 `C` 直接沿用前一段的终点，不需要再写 `M`：

```text
M 0 0 C 0 16 4 28 10 36 C 28 60 64 48 64 0
```

## 为什么两个端点之间也能重合

仅凭起点、切点和终点都对得上，还不能断言曲线没变。可以用每一段两端的**速度向量**来检验。把参数当作时间，速度就是位置对参数的导数，既有方向也有大小。对于控制点为 $Q_0,Q_1,Q_2,Q_3$ 的三次贝塞尔曲线，起点速度是 $3(Q_1-Q_0)$，终点速度是 $3(Q_3-Q_2)$。这两式可直接从三次贝塞尔多项式求导得到。因此给定两端的位置和速度，四个控制点就唯一确定了。

设原曲线为 $p(t)$，切分参数为 $s$，其中 $0<s<1$。把前一段单独拿出来，让它自己的参数 $u$ 也从 0 走到 1，它要描出的就是 $p(su)$。由链式法则，它的起点速度是原来的 $s$ 倍，所以第一个控制柄要从 $P_0$ 朝 $P_1$ 缩到原长的 $s$ 倍。这正是第一层的 $A$。后一段对应 $p(s+(1-s)u)$，终点控制柄也有相同的道理，只是比例换成了 $1-s$，对应表里的 $C$。

切点两侧的控制柄也满足速度条件。把三次贝塞尔多项式求导，可得 $p'(s)=3(E-D)$：导数是由三条相邻控制点差向量按二次贝塞尔权重插值得到的三倍，而对点做两层插值后再作差，恰好就是 $E-D$。最后一次插值又给出 $F=D+s(E-D)$。因此：

$$
3(F-D)=s\,p'(s),\qquad 3(E-F)=(1-s)\,p'(s).
$$

左边两式分别是前一段的终点速度和后一段的起点速度。它们与各自的局部参数完全匹配。两段的端点和速度都确定了，所以重建的是原曲线的两个参数区间，不是用两条相似曲线去逼近它。这个取控制点的方法也适用于更高次数，见[密歇根理工大学的贝塞尔曲线细分图解](https://pages.mtu.edu/~shene/COURSES/cs3621/NOTES/spline/Bezier/bezier-sub.html)。

## 接缝光滑，不等于可以把控制柄镜像

回到例子。抵达切点的柄向量 $F-D=(6,8)$，离开切点的柄向量 $E-F=(18,24)$。两者方向相同，长度却正好相差三倍。原因是两个局部参数都从 0 走到 1，后段却要覆盖原参数区间的四分之三。如果用两段等长的时间播放动画，接点处会突然加速；若想复现原参数运动，两段时间应按 $1:3$ 分配。这仍不等于沿曲线匀速运动。

这里有个很容易写错的简化。[SVG 的平滑三次曲线命令 `S`](https://www.w3.org/TR/SVG/latest/paths.html#PathDataCubicBezierCommands) 会把前一个 `C` 的末端控制点绕接点镜像，用作后一段的第一个控制点。镜像 $D=(4,28)$ 得到 $(16,44)$，而我们需要的是 $E=(28,60)$。改用 `S` 后接缝看上去依然平滑，后半段的形状却已经变了。比如走到后半段自身参数的一半，正确位置是 $(43.75,45)$，镜像柄得到的却是 $(39.25,39)$。

如果恰好从参数中点对半切，两个柄等长，镜像才会自然给出正确结果；切点导数为零时，两柄都缩到切点，谈不上由它们确定切线方向。一般位置上，直接保留插值算出的两个柄即可。这样添加的是一个今后可以拖动的节点，而不是一次悄悄改变轮廓的编辑。
