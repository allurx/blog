三个任务要分给三台机器，每个任务只能运行在一部分机器上，每台机器至多接一个任务。按顺序给任务挑一台空闲机器，很容易得到一个“再也加不进新配对”的结果。但这未必是最多能安排的任务数：让已经安排好的任务换台机器，可能就能腾出位置。

增广路把这种连锁换位变成了精确的图算法。本文讨论有限、无权二分图中的最大匹配：目标只有配对数量，不包含运行成本、偏好排序或负载均衡。读者只需了解图中的顶点、边和路径。

## 加不进去，不代表数量最多

把任务作为左侧顶点，机器作为右侧顶点。任务能在某台机器上运行，就在二者之间连一条边。边只连接左右两侧，这就是二分图。选出的边不能共享端点，否则会出现一个任务被重复安排，或一台机器同时接收两个任务；满足这个要求的边集称为匹配，记作 M。

考虑下面这个例子。表格列出全部允许关系，不存在未列出的配对。

| 任务 | 可以使用的机器 |
| --- | --- |
| A | X、Y |
| B | Y、Z |
| C | X |

假如先选了 A—X、B—Y，轮到 C 时，唯一能用的 X 已被占用，Z 却空闲着。

这个大小为 2 的匹配是**极大匹配**（maximal matching）：在不拆除已有边的前提下，无法再加入一条边。但它不是**最大匹配**（maximum matching），因为 C—X、A—Y、B—Z 能同时成立，数量是 3。

极大描述“不能直接扩展”，最大描述“所有合法方案中数量最多”。这个例子也说明，失败不一定来自机器总量不足，可能只是已有配对挡住了后来的任务。

## 沿着交替路径换位

从未匹配的 C 出发，可以找到下面这条路径：

$$
C \to X \to A \to Y \to B \to Z
$$

它在任务与机器之间来回穿行，每一步的身份如下：

| 路径上的边 | 当前是否属于 M | 换位后的操作 |
| --- | --- | --- |
| C—X | 否 | 加入 |
| A—X | 是 | 移除 |
| A—Y | 否 | 加入 |
| B—Y | 是 | 移除 |
| B—Z | 否 | 加入 |

这些边交替属于匹配和不属于匹配，因此称为交替路径。两端 C、Z 又都未匹配，这使它成为一条**增广路**。[Goemans 的二分图匹配讲义](https://math.mit.edu/~goemans/18453S17/matching-notes.pdf)给出了这两个定义及相应的翻转操作。

翻转后，中间的 X、A、Y、B 都是失去一条旧匹配边，再得到一条新匹配边，仍然各自只参与一个配对。两端则从没有配对变成各有一个。路径之外不作修改，所以整个结果仍是合法匹配。

更一般地，一条增广路若有 k 条旧匹配边，就有 k+1 条非匹配边。移除前者、加入后者，匹配数量恰好增加 1。这也可以写成集合的对称差：

$$
M' = M \mathbin{\triangle} E(P),\qquad |M'|=|M|+1
$$

其中 E(P) 是路径 P 的边集，对称差表示只保留两个集合中恰好出现一次的元素。

不是任何交替路径都能增广。如果终点已经匹配，换位可能只把“未匹配”的位置搬到别处，数量没有增加。交替环也不会增加数量，因为环里的匹配边和非匹配边一样多。端点是否空闲，是判断能否增加配对数的关键条件。

这里的翻转是求解过程中的方案更新。如果配对已经对应真实执行中的任务，迁移、暂停和回滚是否允许是额外约束，不能仅凭图中存在增广路，就直接搬动运行中的工作。

## 搜索时给边规定方向

在二分图里，寻找增广路可以转成普通的有向图可达性问题。对当前匹配 M，规定：非匹配边从左指向右，匹配边从右指向左。然后从所有未匹配的左侧顶点出发，做一次 BFS 或 DFS。

到达右侧顶点时，如果它尚未匹配，就找到了终点。如果它已经匹配，就沿唯一的匹配边回到左侧，再尝试该任务的其他候选机器。访问标记防止重复绕行，前驱记录用于还原路径。上例正好依次走过 C、X、A、Y、B、Z。

下面是概念伪代码，省略了队列、前驱数组和路径恢复的常规实现。它每轮重新搜索当前匹配对应的方向图，不能把上一轮的访问标记继续当成本轮结论。

```text
M = 空匹配

重复:
    按 M 确定每条边的方向
    从所有未匹配的左侧顶点搜索
    若找不到未匹配的右侧顶点:
        返回 M
    沿前驱恢复一条路径 P
    翻转 P 上各条边的匹配状态
```

使用邻接表时，一轮搜索和初始化需要 `O(V+E)` 时间。设左右两侧较小的一侧有 q 个顶点，最多成功增广 q 次，再加一次失败搜索，因此这段朴素算法的时间上界可写为 `O((q+1)(V+E))`，辅助空间为 `O(V)`，不含图本身。更快的 Hopcroft–Karp 算法会分阶段同时处理多条最短增广路；它改变搜索组织方式，保留的仍是这套增广机制。

## 找不到增广路，为什么可以停止

如果找到增广路就能扩大匹配，这已经由翻转证明。反方向更重要：会不会所有增广路都消失了，却仍存在一个需要更复杂重排才能达到的更大匹配？

不会。Berge 定理说明，匹配最大，当且仅当不存在相对于它的增广路。其[对称差证明](https://web.cs.dal.ca/~nzeh/Teaching/4113/book/matching/bipartite_maximum_matching/augmenting_paths.html)也解释了为什么只寻找这种路径就足够。

设当前匹配是 M，另有一个更大的匹配 N。把二者共有的边消去，只看各自独有的边。每个顶点至多连接一条来自 M 的边和一条来自 N 的边，所以剩下的连通部分只能是路径或环，边的归属沿途交替。

交替环中，两种边的数量相同。有些路径中两种边数量也相同。如果所有路径里 N 的边都不比 M 的多，整体上 N 就不可能更大。因此至少有一条路径，来自 N 的边比来自 M 的多一条。它的首尾边都来自 N，两端都未被 M 匹配，恰好就是 M 的一条增广路。

于是，“存在更大匹配”必然推出“存在增广路”。完整搜索找不到增广路时，当前结果便已达到最大数量。这比“没有空闲邻居”强得多：前者排除了任意长度的连锁换位，后者只排除了一步配对。

上述最大性判据适用于一般无向图，但简单的左右定向搜索依赖二分结构。一般图没有固定的左右划分，奇环会给增广路搜索带来额外问题，不能直接照搬这段算法。

## 真正缺少候选位置时

再改一下输入：A、B、C 都只允许使用 X、Y，Z 虽然存在，却不与任何任务相连。现在无论怎样换位，三个任务都在竞争同两个位置，最多匹配 2 个。

这个障碍可以推广。对任意一组左侧顶点 S，用 N(S) 表示它们在右侧的所有邻居。若 `|N(S)| < |S|`，这些任务就不可能全部获得不同位置。Hall 定理进一步说明：对有限二分图，所有这样的子集都满足 `|N(S)| ≥ |S|`，恰好就是存在覆盖整个左侧的匹配的充要条件。这里说的是覆盖左侧；只有左右规模相等时，它才同时覆盖全图。

不必真的枚举所有子集才能解释一次失败。对已经最大、但未覆盖左侧的匹配，从所有未匹配左顶点做上述完整搜索，记可达的左、右顶点集合分别为 S、T。因为没有增广路，T 中每个顶点都已匹配，且它的匹配伙伴属于 S。S 中除搜索起点外的顶点也都由这样的匹配边到达，因而 `|S| > |T|`。此外 S 的每个邻居都在 T 中：非匹配边会被搜索访问，匹配边所连的右顶点则已经是到达该左顶点的前驱。因此 `N(S)=T`，这就找到了一个具体的位置不足的任务集合。

在修改后的例子中，假设已有 A—X、B—Y，搜索从 C 出发，会到达 X、Y，再回到 A、B。最终 S 是三个任务，T 是两台机器。相比只返回“匹配失败”，这份证据指出了问题究竟在哪里：必须为这组任务增加可用位置或候选关系，仅调整分配顺序没有用。

增广路解决的是最大数量问题。若不同配对带有价格，任意增广得到的最大匹配未必最便宜；若每台机器可接多个任务，也需改成容量模型。对本文的一对一无权模型，思路则很完整：先允许旧方案沿路径调整，直到不存在增广路，再用可达集合解释未能安排的任务受到什么限制。
