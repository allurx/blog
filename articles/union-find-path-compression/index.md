并查集（Union-Find，也称 Disjoint Set Union）维护一组互不相交的集合，常用来回答两个元素是否连通，并把两个集合合并。它把每个集合表示成一棵有根树，却会在查询时主动改写这棵树：`find` 找到根后，让路径上的节点直接指向根。

这种“边查边改”容易产生一个疑问：父指针既然代表集合结构，路径压缩为什么不会改变集合成员，甚至把原本不同的集合误连起来？答案在于并查集维护的是分区，不是树的具体形状。父指针可以改写，只要每个节点仍指向本集合中的祖先，并且根没有变。

## 森林只是分区的一种编码

初始时，每个元素都是一棵只含自身的树，父指针指向自己：

```text
parent[x] = x
```

一棵树中的根充当该集合的代表元。`find(x)` 沿父指针走到满足 `parent[root] == root` 的节点，并返回这个根。两个元素属于同一集合，当且仅当它们的 `find` 结果相同。

这里真正需要保持的是两个不变量：

1. 每个节点沿父指针最终能到达唯一的根，不能形成不含根的环。
2. 一条父子边的两个端点始终属于同一个集合。

树的高度、节点挂在哪个中间父节点下，都不是集合语义的一部分。只要根的划分没有变化，同一集合可以对应许多种不同形状的树。

## 路径压缩只删除中间跳转

设一次查询走过下面的路径：

```text
7 → 5 → 2 → 2
```

根是 2，因此 7、5、2 已经属于同一个集合。普通查询只返回 2；路径压缩还会把访问过的非根节点改为直接指向 2：

```text
7 ─┐
5 ─┼→ 2 → 2
```

改写前，7 通过 5 到达 2；改写后，7 直接到达 2。它的代表元没有变化。5 也只是跳过了原路径中的中间节点。整个过程没有选择另一棵树的根，所以不会合并原本不同的集合。

递归写法把“先找到根，再在返回途中改写父指针”表达得很直接：

```text
find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]
```

赋值右侧返回的是 `x` 原先沿父链可达的根。赋值后，新边从 `x` 指向同一个根，因此仍满足“父边不跨集合”的不变量。对递归路径上的节点逐个应用这个论证，压缩后的整棵树仍表示原来的集合。

路径压缩也不会制造环。根仍指向自己，其他被改写的节点都指向根；一条指向根的边不可能再返回非根节点。

## 真正改变分区的是合并

`union(a, b)` 才会改变集合划分。它先分别找到两个根；若根相同，两个元素本来就在同一集合，不需要修改。若根不同，只把一个根挂到另一个根下面：

```text
union(a, b):
    rootA = find(a)
    rootB = find(b)

    if rootA == rootB:
        return

    parent[rootB] = rootA
```

限制修改对象为根很重要。若直接执行 `parent[b] = a`，而 `b` 不是根，就只会搬动 `b` 所在的子树；原集合可能被拆成两部分，分区语义随即被破坏。

实际实现通常按大小或秩合并。以按大小合并为例，总让较小树的根指向较大树的根：

```text
if size[rootA] < size[rootB]:
    swap(rootA, rootB)

parent[rootB] = rootA
size[rootA] += size[rootB]
```

`size` 只对根有意义。路径压缩会改变树的形状，却不会改变集合中元素的数量，所以不需要沿压缩路径更新它。若采用按秩合并，秩同样是合并策略使用的上界信息，不应在路径压缩后把它误当作当前树高重新计算。

## 两种优化解决不同的问题

按大小或按秩合并限制树在合并时长高：一个节点的深度每增加一次，它所在集合的规模至少翻倍，因此只用这种合并策略时，树高至多是对数级。

路径压缩则利用已经发生的查询，把后续访问会经过的长链拉平。一次 `find` 仍可能走过很多节点；它的价值体现在这次遍历为后续操作预付了工作。

两种策略同时使用时，包含 `make-set`、`find` 和 `union` 的操作序列具有近乎线性的总成本，通常写成每次操作摊还 $O(\alpha(n))$，其中 $\alpha$ 是增长极慢的 Ackermann 函数反函数。这里有两个必要限定：

- 这是操作序列的**摊还复杂度**，不表示每一次 `find` 的最坏情况都是常数时间。
- 该界依赖平衡合并与路径压缩的组合，不能把任意父指针连接方式都直接标成 $O(\alpha(n))$。

[Tarjan 1975 年的论文](https://doi.org/10.1145/321879.321884)给出了这一经典组合的紧确渐近分析；Cornell University Library 也保存了[论文技术报告版本](https://hdl.handle.net/1813/5942)。后续对路径压缩、路径分裂和路径折半等变体的比较，可见 Tarjan 与 van Leeuwen 的[最坏情况分析](https://doi.org/10.1145/62.2160)。这些结论分析的是一串交错操作，而不是把单次树遍历宣称为无条件常数时间。

## 压缩带来的限制

路径压缩通过覆盖父指针换取后续查询更快，这也决定了它的边界。

需要回滚到旧状态时，原父链本身就是历史信息。直接压缩会一次改写多个节点，使撤销操作必须额外记录所有变化；常见的可回滚并查集因此会关闭路径压缩，只采用易于记录和撤销的按大小合并。

并查集也不原生支持删除一条连接后把集合拆开。树中的父边只是集合编码，不对应当初输入的某一条业务边；压缩后这种对应关系更不存在。需要在线删除或拆分时，应使用适合动态连通性的其他结构，不能尝试“恢复某个父指针”来撤销连接。

并发环境还需要单独设计同步协议。顺序算法中的不变量证明说明一次压缩在完整执行后保持分区，却不保证多个线程无同步地读写同一父数组仍然安全。

路径压缩的正确性最终只依赖一个简单事实：查询路径上的所有节点原本就拥有同一个根。把这些节点改为直接指向该根，改变了到达代表元的路线，没有改变代表元本身。并查集利用这种表示自由，把过去查询发现的信息写回森林，从而让将来的查询更短。
