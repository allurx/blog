有序链表很适合顺序遍历和在已知位置后插入，但查找第一个不小于目标值的元素时，只能从头逐个比较。即使链表已经排序，查找仍要走 $O(n)$ 个节点。跳表（skip list）在链表上方增加越来越稀疏的“快车道”：先在高层跨过大段区间，不能继续向右时下降一层，最终在最底层确定答案。

这些快车道不靠旋转或全局重排维持严格平衡。每个新节点独立地随机决定自己能升到多高，整体仍能得到期望 $O(\log n)$ 的查找、插入和删除时间。本文要解释的正是这一步：局部抛硬币为什么会形成可用的全局索引，以及这种保证与平衡树的最坏情况保证有什么不同。读者只需熟悉有序链表和大 O 记号。

## 多层链表把长距离移动变成逐层缩小范围

跳表的第 0 层包含所有节点，保证它始终是一条完整的有序链表。更高层只保留部分节点，并用指针连接同层的下一个节点。一个节点出现在第 $i$ 层，也必然出现在所有更低层。

下面的结构中，第 2 层最稀疏，第 0 层最完整：

```text
L2  head ----------------> 21 ----------------> 42
L1  head ------> 8 ------> 21 ------> 34 ------> 42
L0  head -> 3 -> 8 -> 13 -> 21 -> 27 -> 34 -> 39 -> 42
```

查找 39 时，从最高层的 `head` 开始。第 2 层先走到 21，42 已超过目标，于是下降；第 1 层从 21 走到 34，再因 42 太大而下降；第 0 层只需从 34 走到 39。算法在每一层都保持一个不大于目标的最右节点，所以下降后不必退回链表头部。

用伪代码表示，查找过程只有“能向右就向右，否则下降”这一条主线：

```text
x = head
for level = currentMaxLevel down to 0:
    while x.next[level] exists and x.next[level].key < target:
        x = x.next[level]
return x.next[0]  // 它是第一个不小于 target 的节点
```

高层指针的价值不在于直接命中目标，而在于安全地排除一整段较小的键。所有实际答案仍由包含全部节点的第 0 层给出。

## 独立晋升自然形成几何递减的索引

插入节点时，先让它进入第 0 层，再以固定概率 $p$ 决定是否晋升一层；每成功一次就用同样规则决定是否继续晋升，直到第一次失败或达到实现规定的最高层。若层号从 0 开始，则节点至少达到第 $i$ 层的概率为：

$$
\Pr(H \ge i) = p^i
$$

对于 $n$ 个节点，第 $i$ 层的期望节点数因此是 $np^i$。令最高的非空层附近只剩常数量级的节点，即 $np^h \approx 1$，得到：

$$
h \approx \log_{1/p} n
$$

这解释了层数为何只随数据规模对数增长。以常见的 $p=1/2$ 为例，期望上每升一层节点数减半：底层约有 $n$ 个节点，上一层约有 $n/2$ 个，再上一层约有 $n/4$ 个。到第 $\log_2 n$ 层附近，通常只剩少量节点。

搜索的横向工作同样受这个几何分布约束。直观地反向观察一条搜索路径：在某层向左经过的节点，要么很快遇到一个也晋升到上一层的节点，要么继续经过未晋升节点；独立晋升使这段长度服从尾部指数衰减的分布，期望只与 $p$ 有关。每层的期望横向步数是常数，而期望层数是 $O(\log n)$，两者相乘便得到期望 $O(\log n)$ 的查找成本。

节点携带的指针数量也有清楚的期望值。每个节点有一个第 0 层指针，继续拥有第 1、2、3 层指针的概率依次为 $p$、$p^2$、$p^3$，所以：

$$
\mathbb{E}[\text{pointers per node}]
= 1 + p + p^2 + \cdots
= \frac{1}{1-p}
$$

$p=1/2$ 时平均为 2 个指针；降低 $p$ 会减少指针和层内节点，同时让每层可能需要更多横向比较。它是时间、空间与常数开销之间的选择，并不存在脱离工作负载的唯一最优值。

## 插入先记录每层前驱，再一次性接入新节点

随机层级只决定新节点有多少条前向指针，正确插入仍要找到每一层的连接位置。搜索插入位置时，用 `update[i]` 记录第 $i$ 层最后一个小于待插入键的节点。假设新节点随机得到层级 $k$，随后只需在第 0 到第 $k$ 层各改两条关系：

```text
node.next[i] = update[i].next[i]
update[i].next[i] = node
```

删除也复用同一组前驱：如果 `update[i].next[i]` 正是目标节点，就把它改为目标的后继。普通单线程实现不需要像 AVL 树或红黑树那样在更新后沿路径旋转；概率平衡来自节点层级分布，而不是每次操作后的结构修复。

这不表示任意几行链表代码都自动安全。完整实现至少要明确以下契约：

- **重复键策略**：集合可以拒绝重复键，映射可以覆盖同键值，多重集合则要规定相等元素的顺序。搜索、插入和删除必须使用同一规则。
- **最高层限制**：实现通常设置 `maxLevel`，避免节点保存无界数组。上限应结合预期容量和 $p$ 选择；截断过低会让最顶层仍然过密，退化为更多横向扫描。
- **随机性来源**：层级选择需要与键值和插入顺序充分独立。普通内存索引通常不需要密码学随机数，但可预测或有偏的低质量生成器会破坏分析前提。
- **并发协议**：单线程指针改写不能直接变成无锁并发实现。并发跳表还要处理发布顺序、逻辑删除、内存回收及搜索与更新的交错，这是一组独立的正确性问题。

随文的 [可执行示例](./skip-list-demo.mjs) 使用固定种子的伪随机数生成器，便于复现层级和搜索路径。它实现唯一数字集合，并输出每一层的节点以及查找 39 时的移动过程：

```sh
node skip-list-demo.mjs
```

固定种子只服务于演示可重复性，不能用于需要抵抗恶意输入的场景。

## 概率保证不能改写成确定的最坏情况保证

跳表可能抽到很差的结构。极端情况下所有节点都停留在第 0 层，查找便退化为 $O(n)$；也可能出现异常高的节点。随机晋升使这些坏结构的概率迅速下降，却没有让单次操作获得平衡树那样的确定性 $O(\log n)$ 最坏情况上界。

[William Pugh 最初发表于 1990 年的论文](https://doi.org/10.1145/78973.78977)将这种差别概括为概率平衡，并分析了搜索时间显著超过期望值的概率。[University of Maryland 保存的后续技术报告](https://drum.lib.umd.edu/items/56c44671-3973-46b6-9e52-f71dc95af178)进一步讨论了基于跳表的合并、分裂、按秩操作和搜索指针。这里使用的是基础字典操作：它们的期望复杂度依赖独立随机层级，不应外推为实时系统的硬截止保证。

选择数据结构时，可以据此区分两类需求。若系统必须为每次操作提供确定的最坏情况上界，严格平衡树更直接；若更看重实现简洁、顺序遍历和期望性能，并且能接受极小概率的长路径，跳表很有吸引力。对于暴露给攻击者的服务，还要把随机数质量、输入可控程度和拒绝服务风险纳入判断，不能只引用平均复杂度。

随机层级并没有神奇地预测数据分布。它只是让每个节点独立参加逐层抽样：第 $i$ 层以约 $p^i$ 的比例保留底层节点，于是形成从稠密到稀疏的一组有序索引。搜索在每层做期望常数次横向移动，再下降对数数量的层；插入和删除沿同一条路径更新局部指针。跳表的简洁来自这个局部规则，而它的边界也来自同一个地方——得到的是期望与高概率意义上的平衡，不是确定性平衡。
