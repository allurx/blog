给定一列元素，如果某个值出现次数严格超过总数的一半，就称它为多数元素。用哈希表统计频次很直接，但需要保存不同元素及其计数。Boyer–Moore 多数投票算法只维护一个候选值和一个计数器，第一遍就能筛出候选，额外空间为常数。

容易误解的是，第一遍结束时的候选不一定真占多数。算法只有在“多数元素确实存在”这个前提下，才能保证候选正确；当前提没有由调用方保证，就必须再扫描一次验证。本文从成对抵消推导这两个结论，并说明计数器为什么不能直接充当候选的出现次数。

## 不同元素可以成对删除

设序列长度为 n，多数元素 M 出现 m 次，其中 $m > n/2$。从序列中任意删除两个不同的元素，不会改变多数元素的身份。

若删除的一对包含 M，新的数量为：

$$
m' = m - 1, \qquad n' = n - 2.
$$

由 $m > n/2$ 可得：

$$
m - 1 > \frac{n-2}{2}.
$$

M 在剩余元素中仍然严格过半。若删除的一对不含 M，M 的数量不变而总数减少 2，它更不可能失去多数地位。因此，只要原序列存在多数元素，反复消去不同元素组成的配对，最后留下的值一定是 M。

这个推导只保留“多数是谁”，不保留原始频次。配对中被删除的两个值可能都很常见，算法也不关心它们在原序列里的位置。

## 候选值与余额模拟抵消

第一遍扫描可以写成下面的伪代码：

```text
candidate = 未设置
balance = 0

for value in values:
    if balance == 0:
        candidate = value
        balance = 1
    else if value == candidate:
        balance += 1
    else:
        balance -= 1
```

`balance` 表示尚未被其他值抵消的候选副本数。遇到相同值就多保留一份，遇到不同值就与一份候选配成一对并抵消。余额归零时，此前尚未抵消的候选也已全部配对；下一项可以成为新候选，不必记住已经消完的部分。

以 `[A, B, A, C, A, A, D]` 为例，A 出现 4 次，是 7 个元素中的多数：

| 读入值 | 扫描后的候选 | `balance` | 本步含义 |
| --- | --- | ---: | --- |
| A | A | 1 | 建立候选 |
| B | — | 0 | A 与 B 抵消 |
| A | A | 1 | 重新建立候选 |
| C | — | 0 | A 与 C 抵消 |
| A | A | 1 | 重新建立候选 |
| A | A | 2 | 多一份未抵消的 A |
| D | A | 1 | D 抵消一份 A |

表中余额为 0 时用“—”表示当前没有有效候选；实现可以保留变量里的旧值，因为下一项会先覆盖它。扫描结束只剩候选 A 和正余额 1。余额不是 A 的出现次数 4，而是完成一组合法抵消后剩余的净数量。

这也给出了正确性证明。第一遍所做的每次减法都等价于删除一对不同元素；余额归零则表示当前这组元素已完全成对消去。若输入中确有多数元素，成对删除始终保留它的多数地位，最终未抵消的候选只能是它。

## 没有多数时也可能留下候选

再看 `[A, B, C]`：A 与 B 抵消，随后 C 成为候选，最终余额为 1。C 只出现一次，显然没有超过 $3/2$。算法没有出错，因为第一遍证明的是一个条件命题：

> 如果多数元素存在，那么最终候选就是多数元素。

它没有证明多数元素必然存在。不同元素两两抵消后出现幸存者，只说明抵消过程最后没有清空，不能反推出幸存者在原序列中严格过半。类似地，Boyer–Moore 也不是求众数的算法；在 `[A, A, B, B, C]` 中，最终候选可以是 C，但出现最多的是 A 和 B。

因此，在没有外部保证时要执行第二遍：

```text
occurrences = 0
for value in values:
    if value == candidate:
        occurrences += 1

if occurrences > length(values) / 2:
    return candidate
else:
    return 不存在多数元素
```

必须使用严格大于。偶数长度序列中恰好出现一半的值不是多数元素；两个不同值也可能各占一半，无法同时严格过半。

## 第一遍的余额不能替代验证计数

扫描时曾被抵消的候选副本不会计入最终余额，候选还可能在中途多次更换。第一遍只保存了足以确定条件候选的信息，没有保存候选在整个输入中的准确频次。把最终 `balance` 与 `n/2` 比较会得到错误结论：前面的七元素示例中 A 确实占多数，最终余额却只有 1。

如果题目契约明确承诺多数元素一定存在，第一遍候选已经足够，可以省略验证。若输入是不可重放的数据流，又没有这项承诺，则应在读取前安排重放、落盘或采用符合实际阈值问题的流式摘要；不能把未验证的候选包装成确定答案。

[Boyer 和 Moore 的原始论文](https://www.cs.utexas.edu/~boyer/mjrty.pdf)把该算法称为 MJRTY，并给出常数存储、比较次数不超过投票数两倍的上界及机械验证过的实现。Moore 的[算法说明页](https://www.cs.utexas.edu/~moore/best-ideas/mjrty/)也准确保留了关键前提：第一遍在多数元素存在时决定它是谁。

Boyer–Moore 投票节省空间的依据不是“赢家一路领先”，而是严格多数经不同元素成对删除后仍是严格多数。第一遍利用这个不变量找出唯一可能的答案；第二遍则检查题目是否真的满足前提。把候选筛选与存在性验证分开，才是这套算法完整的契约。
