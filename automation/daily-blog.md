# 博客写作任务

为 allurx 博客完成计算机相关的正式文章，提交到 `allurx/blog` 的 `main`，并核验既定自动发布结果。本任务已获授权提交、推送本次文章并触发自动发布，不建立草稿、审核或待发布队列。

定时执行每天生成一篇；用户每次主动手动新增，都额外生成一篇独立文章，不因当天已有文章而跳过。手动新增不抵消当天的定时生成。同一次执行的失败重试只恢复原成果，不额外生成。内容查重独立进行，同日多篇本身不是重复。

## 开始与恢复

从 GitHub 最新 `main` 读取 [AGENTS.md](../AGENTS.md)，按其入口继续读取写作标准和相关维护说明，再开展选题与写作。按开始时的 `Asia/Shanghai` 日期确定当天，跨午夜仍沿用该日期，不补写过去缺失日期。

先识别这次是定时生成、手动新增，还是恢复一次未完成的执行。使用当前用户明确指令或运行环境实际提供的触发来源，不根据执行时间、聊天名称、已有文章日期或固定提示词中的“每日”猜测。用户说“再写一篇”“手动新增一篇”属于新增；“继续完成”“重试刚才的任务”属于恢复，不能重新分配新增标识。

不同触发使用不同的成果标识：

| 触发方式 | 提交标题与恢复规则 |
| --- | --- |
| 定时生成 | `docs(blog): scheduled article YYYY-MM-DD`，日期为本次首次开始的任务日期。同一定时日期只对应一篇，重复投递或失败重试沿用该标识。 |
| 手动新增 | `docs(blog): manual article <UUID>`。每次独立新增请求在首次执行时生成一个 UUID，并在写入前保留到本次执行上下文；同日其他请求使用不同 UUID。不能使用日期或聊天 ID 代替它。 |
| 恢复执行 | 沿用原触发方式、标识、任务日期、目录和正文，不生成新的 UUID，不把重试当作手动新增。 |

先从最新 `main` 历史查找与本次标识完全匹配的提交，再回读文章及附件。找到本次已保存成果时，补完缺少的验证或发布；没有找到提交时，先检查本次已有正文及结果不明的写入，再从尚未完成的阶段继续。定时与手动标识分别查找，不能因另一个标识已经成功而跳过本次新增。提交标题只帮助识别成果，不证明内容完整或发布成功。

调用入口应明确传入“定时生成”或“手动新增”；重试应保留原执行上下文或提供原标识。平台界面的“立即运行”按钮不保证模型能收到对应的触发类型，不能仅凭按钮名称推断。若环境只提供相同的保存提示词、无法辨别来源，需补充明确的触发说明；可在聊天中发送“手动新增一篇博客文章”表达新增意图。恢复时缺少原标识，应先定位原请求、正文与提交，仍有歧义则报告缺口，不能盲目换标识重写。

执行归属根据可确认的上下文、正文和提交判断，不按文章 `date` 合并。执行标识只保留在执行上下文和 Git 提交中，不写进文章元数据或正文，也不另建运行台账。

## 选题与写作

按[写作指南](../docs/writing.md#选题与读者)在计算机相关的所有知识领域自主选题，兼顾基础原理、技术实现与相关应用，不固定技术栈、示例语言或栏目配额。每篇围绕一个独立的学习目标展开，不要求一篇覆盖整个领域。先独立选择候选主题，再检索已有文章；已有文章只用于查重，不作为选题池，不用近期内容限定后续领域。

先形成候选主题，再按核心概念、API、常见中英文名称和同义词定向检索已有文章。先读命中的元数据和相关段落，确有重合可能时再读全文，按[新增与修订的判断](../docs/writing.md#新增与修订的判断)比较问题、适用条件、结论和示例。无需每次全量读取站点标题、标签、摘要或固定时间段的正文；证据不足时再扩大范围，检索不完整时说明限制。

目录名仅检查路径唯一，不能代替内容查重。新稿与已有文章实质重复且没有独立价值时另选主题；本任务没有顺带修订其他文章的授权。允许必要的前置知识重叠，不用换标题、增加序号或日期绕过去重。

以简体中文写成独立文章，按主题交代前置知识并选择合适的示例形式。来源、论证、示例、图片和附件统一遵循写作指南，执行记录与发布核验不写进正文。

## 保存与交付

按写作指南审稿并完成仓库要求的验证。保存前重新读取最新 `main`，核对本任务是否已保存、候选内容是否重合以及目录是否被占用；其他作者新增的同日文章保留。本任务已完成时恢复已有成果；目录同名但内容确实独立的，使用能准确区分主题的限定词，不覆盖既有文章。

使用与本次执行标识对应的提交标题，以一次原子提交保存正文及必需附件。`main` 在保存期间推进时，回读最新历史，在其基础上重新整合本篇内容并验证，不用旧 tree 覆盖新提交，不强推或改写历史。本任务仅获准写入本次文章及附件，不修改任务日程、平台权限、域名配置或其他文章。

提交后回读 commit SHA、正文和附件字节，再按[发布指南](../docs/deployment.md#自动发布)核对该提交的构建、部署及公开文章，检查实际标题、日期、关键正文和附件。缺少执行或核验能力时说明具体缺口，按仓库约束检查对应 Cloudflare 构建结果；失败时保留已完成成果和恢复依据，不重新生成文章补偿发布失败。

成功时最终回复严格只输出一行：`博客文章已发布：[文章标题](文章链接)`，使用实际标题和经核实的文章链接，不附摘要、提交链接、过程记录或其他段落；失败时明确已保存内容、未完成阶段和具体阻塞。不另建运行台账或重复任务。
