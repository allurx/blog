# 每日博客文章

每天为 allurx 技术博客完成一篇正式的软件工程文章，提交到 `allurx/blog` 的 `main`，并核验既定自动发布结果。本任务已获授权提交、推送当日文章并触发自动发布，不建立草稿、审核或待发布队列。

## 开始与去重

从 GitHub 最新 `main` 读取 [AGENTS.md](../AGENTS.md)，按其入口继续读取写作标准和相关维护说明，再开展选题与写作。按开始时的 `Asia/Shanghai` 日期确定当天，跨午夜仍沿用该日期，不补写过去缺失日期。

先核对当天的文章和提交。已有完整文章时只补完核验或发布；同日多篇、ID 或内容冲突时保留现状并报告，不覆盖、删除或换 ID 绕过。重试沿用已保存的日期、ID 和正文，写入结果不明时先回读文件与提交记录。

## 选题与写作

从 Java、JDK/JVM、Spring、数据库、缓存、消息队列、并发、分布式、性能、系统设计、TypeScript/JavaScript、Web、Git、Linux、AI/Agent/MCP 中自主选择一个有工程价值的具体问题。先读最近 30 自然日文章的标题、元数据和必要正文，再按候选概念检索更早相关文章。重访主题须有新场景、新版本或新证据，不用换标题制造重复文章；检索不完整时说明范围。

面向有编程经验的读者，以简体中文写成独立文章，示例代码优先 Java 或 TypeScript。不把执行日志和内部检查表写进正文。

## 保存与交付

按已读取的写作标准审稿，完成仓库要求的验证。基于最新 `main`，以一次原子提交保存正文及必需附件；`main` 已推进时重新读取并整合本篇内容，不用旧 tree 覆盖新提交。此任务仅获准写入当日文章及附件，不修改任务日程、平台权限、域名配置或其他文章。

提交后回读 commit SHA、正文和附件字节，并核对该提交的构建、部署及公开文章，检查标题、日期、关键正文和附件。缺少执行或核验能力时说明具体缺口，按仓库约束检查对应构建结果；失败时保留已完成成果和恢复依据，不重新生成文章补偿发布失败。

正常交付只给标题、2–3 句摘要、GitHub 提交链接和经核实的文章链接；失败时明确已保存内容、未完成阶段和具体阻塞。不另建运行台账或重复任务。
