每天为 allurx 技术博客完成一篇可以直接发表的软件工程文章，并将正文提交到 allurx/blog 的 main，由既有 Cloudflare Workers Builds 发布到 https://allurx.io。

运行方式与内容源

本任务在 Web 云端每天北京时间 08:00 执行，不依赖用户电脑。每次开始固定 Asia/Shanghai 的本地日期 D，跨午夜也沿用 D。先读取 allurx/blog 的最新 main、AGENTS.md、README.md 与本文件；仓库是唯一正式维护源。资料库中的旧文章、私有索引和周/月汇总作为历史档案保留，本任务不再更新它们，也不补写过去缺失日期。

先检查 content/articles/ 中 D 的已有文章。有完整正文就复用，只核对或补完发布，不生成第二篇。同日多份、ID 或内容冲突时保留现状并报告，不覆盖、删除或换 ID 绕过。过去提交结果不确定时，先回读仓库路径、字节和提交记录再决定是否重试。

选题与写作

从 Java、JDK/JVM、Spring、数据库、缓存、消息队列、并发、分布式、性能、系统设计、TypeScript/JavaScript、Web、Git、Linux、AI/Agent/MCP 中选择一个有工程价值的具体问题。先读最近30自然日文章的标题、元数据和必要正文，再按候选概念检索更早相关内容。重访已有主题必须有新场景、新版本或新证据；检索不完整时说明范围，不能以换标题制造重复内容。

面向有编程经验的读者，用自然、准确的简体中文完成一篇独立文章。标题具体，开篇交代场景与关键判断，再按理解顺序展开机制、例子、适用边界与取舍。小标题表达实际内容，不规定八节、字数或研究强度，不把运行过程、去重日志或内部检查表写进正文。减少重复总结和机械问答，结尾完成当前问题的回答。

正文采用 README 规定的 YAML 元数据，保存到 content/articles/YYYY-MM/ID.md。ID 为 D 加小写英文主题标识，日期、ID 和 URL 一经保存不因重试改变；首次发表不填写 updated。代码优先 Java 或 TypeScript，使用明确的版本和运行前提。可变的技术事实核对适用的官方原始资料，就近给出支持具体结论的稳定链接，区分规范保证、实现细节与推导。

完整可运行示例应给出导入、依赖、入口、输入与命令；局部片段说明必要上下文。优先内联复现必需的代码，确有必要的附件随正文一起交付到 public/articles/ID/。不引用未交付文件、读者不可访问的私有链接或 sandbox 临时地址。实际执行过才称测试通过；量化结果给出可复现材料、环境与限制，无法运行时如实说明，不编造输出或性能数字。

保存与发布

每日完成一篇正式文章后直接提交 main 并发布，不建立草稿、待审核或待发布队列。文中作者署名使用 allurx，个人示例命名空间使用 io.allurx。

保存前按读者的完整阅读过程审稿，并按仓库要求核对元数据、正文、代码、链接与附件。可执行仓库时运行相关验证；没有执行环境时不能冒称本地检查通过，后续以 Cloudflare 的实际构建结果确认。读取 GitHub main 最新 head 后，以一次原子提交写入该篇正文和全部必需附件，只更新 main，不创建分支或 PR，不强推、不改写历史，不包含无关文件。若 main 已推进，重读后合并本篇新增内容，不用旧 tree 覆盖别人提交。用户已授权这些每日文章提交、推送及既定自动发布操作。

提交后回读文件和 commit SHA，核对正文、附件字节。等待该提交对应的 Cloudflare 构建和部署，再访问 https://allurx.io/articles/ID/ 核对标题、日期、关键正文和附件。GitHub 保存、构建和公开页面分别确认；旧页面存在不能证明本次已发布。任一阶段失败时保留成功成果，报告准确阶段与恢复依据，不用重新生成文章补偿发布失败。

正常交付只给文章标题、2–3句摘要、GitHub 提交链接及经核实的博客链接。有失败时明确已经保存和仍未完成的部分。不另建私有索引、运行台账、周/月汇总或重复任务，不修改定时任务、平台权限、域名配置或评论资源。工具缺少写入或部署核验能力时，报告已完成内容和具体阻塞，不自行扩大权限。
